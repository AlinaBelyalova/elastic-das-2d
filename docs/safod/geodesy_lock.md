# SAFOD: воспроизводимое преобразование горизонтальных координат

Проверка 2026-10-25. Исправление применяется поверх `eeaf3ad` и не меняет
источники, траекторию кабеля, MD/TVD, высоту устья или геометрию приёмников.

## Что произошло

`Transformer.from_crs(4326, 26710)` фиксировал исходную и конечную CRS, но
оставлял выбор операции PROJ. Один маршрут использует параметрическое
преобразование NAD27 -> WGS84 (6); другой — две таблицы NADCON/HARN через
NAD83. Версия базы, доступность таблиц, пути поиска и настройки сети могут
изменить выбор. Добавление событий само по себе не должно менять старые
координаты при неизменной операции.

Независимый пересчёт исходного Excel и 291 прежнего источника полностью
воспроизвёл расхождения, присланные с Sherlock:

| Величина | Результат |
| --- | --- |
| max абсолютного изменения Easting | 3.729839480366 м |
| max абсолютного изменения Northing | 3.389906160068 м |
| min/median/max изменения расстояния | -4.473482919 / -0.201128365 / +2.680512940 м |
| NC75379261: старое расстояние | 1570.197269303492 м |
| NC75379261: новое расстояние | 1570.279943596663 м |

Старый результат воспроизводится маршрутом NAD27 -> WGS84 (6), номинальная
точность 7 м. Новый — inverse EPSG:1750 + inverse EPSG:1241 + UTM 10N,
номинальная точность 2.15 м. Это заявленные характеристики операции, а не
гарантированная точность землетрясений или исходной съёмки.

В старых продуктах не записаны маршрут, таблицы и их контрольные суммы.
Поэтому восстановлен численный источник расхождения, но невозможно доказать,
какая именно настройка/таблица изменилась между двумя запусками на Sherlock.

## Независимый геодезический контроль

Предпочтительная пара из SAFOD_geographic_Coords: WGS84
lat=35.9742039, lon=-120.5521414; NAD27/UTM 10N
E=720807.06, N=3983663.97 м.

- Старый маршрут: E=720805.272565812, N=3983665.995291531 м;
  невязка к документу 2.701245 м.
- Новый маршрут: E=720807.238115517, N=3983663.830784464 м;
  невязка 0.226067 м.

Это поддерживает новый маршрут; возвращение старого только ради совпадения
metadata не оправдано. Одной контрольной парой нельзя доказать абсолютную
точность всех точек.

В Excel нулевая точка WGS84 немного отличается от предпочтительного положения
устья: около 1.44 м. Для нового преобразования невязка её WGS84 и NAD27 пары
около 1.665 м. Исходные колонки сохранены как предоставлены; дополнительный
сдвиг для искусственного совпадения не вводится.

## Что фиксирует исправление

`src/safod/nad27.py` задаёт один явный pipeline и использует две небольшие
public-domain NOAA таблицы из `src/safod/nad27_grids/` по абсолютным путям.
Перед созданием преобразования проверяются SHA256. Нет обращения к сети,
автоматического выбора другой операции или молчаливого fallback.

Операция ограничена её документированной областью California-South;
50-километровая область каталога SAFOD находится внутри неё. Для запроса
за пределами области нужен отдельно проверенный маршрут, а не экстраполяция.

Каталог сохраняет описание в `catalog_horizontal_transform.json` и
`CATALOG_NOTES.md`. Диагностика Zhang wellhead QC использует обратную операцию
того же pipeline. Явные альтернативные CRS generic-конструктора сохраняются.

## Что не меняется

- authoritative NAD27 Easting/Northing кабеля, MD, TVD и регистрация каналов;
- трактовка MD/TVD как глубин от GL, без добавления/вычитания 31 ft;
- высота каталога 660.5 м MSL и высота модельной поверхности 660.46 м;
- каталоговые latitude/longitude/depth и профильная проекция из WGS84;
- 3-D Zhang/Lin/EikoHypoTomo P/S: они используют географические координаты,
  не source_east_m/source_north_m из каталога;
- 2-D forward и подготовленные waveform packages.

## Применение и проверка на Sherlock

Патч содержит бинарные grid-файлы; применять обычным `git apply`:

```bash
git apply --check safod_nad27_reproducible.patch &&
git apply safod_nad27_reproducible.patch
```

Проверка текущих 431 строк — только чтение, без запроса NCEDC и изменения CSV:

```bash
FWI=/home/groups/ettore88/alina/.envs/fwi/bin/python
"$FWI" -m scripts.validation.safod.catalog_geodesy \
  --geometry /home/groups/ettore88/alina/SAFOD/SAFOD_Phase2_GeoReferenced_Channels.xlsx
```

Ожидается `checked_events: 431`, `passed: true`, `mismatch_count: 0`.
Допуск 1 микрометр относится только к воспроизведению численных результатов,
не к физической точности. Старые 291 строки metadata по-прежнему содержат
старые расстояния: фиксация маршрута не переписывает готовые картинки/JSON.
Их обновление следует выполнять обычной перерисовкой; P/S cache остаётся валиден.

При следующем построении каталога можно использовать одновременно
`--reuse-manifest --reuse-events`: новые 463 NCEDC записи уже получены.
Ни сканирование файлов, ни повторный сетевой запрос для фиксации не нужны.
